# Implementation review, 2026-09-19

Two-axis code review (Standards, Spec) since the scaffold commit `242dc0b`, a
deep-module review of every module, and Fable's own inspection of real outputs
(cards, drafts, slides, the first gate runs). Findings are listed with what
was done about them. Anything not fixed is a suggestion with a reason.

## Suggestions, deliberately not done today

- **A composition module** (`src/newsroom/compose.ts`) so `daily`, `gate` and
  `publish` share one construction and the env-to-config mapping is testable.
  `cli.ts` is still the only untested policy holder. Worth doing in week two.
- **Narrow `DailyDeps`**: bind `home` and `dirs` at the root the way `fetch`
  already is, so the runner stops knowing directories exist (11 fields → 8).
- **Reuse one Chromium in the gate** (`RenderOptions.browser` exists and is
  never passed). Saves ~200 ms per run; cosmetic.
- **Inject the GitHub token** into the image host instead of shelling out to
  `gh auth token` at module level.
- **Two tests assert mechanism, not behaviour** (`render/index.test.ts` class
  names; `writer.test.ts` "reads the guides once" parsing the HTTP body). Keep
  until the writer accepts a `Generate` with recorded calls at its seam.
- **Gate acceptance cases** from the verdict (deadline before 3 pm, wake after
  an event's window, approved draft with an unresolved flag): the first two are
  unit tests now (`store/publish-by.test.ts`, `shortlist/publish-window.test.ts`,
  the publisher's expiry tests); the third is satisfied by design (approve means
  every flag was confirmed) and by the card test that prints every flag.
- **Fallback pillar in the runner**: when a sourced pillar has no material, the
  runner should switch to an explainer rather than let the model write a
  "quiet week" post that claims sources were scanned. Cheap; next.
- **Launch photos**: no Launch Library image passes the whitelist in real data.
  A NASA image search adapter (public domain) is the honest way to get photos
  on launch cards. Week two.
- **Opportunities and neighbors sources** are still stubs; the week-one plan
  avoids those pillars.

## Kept as is, on purpose

`publisher/machine.ts` (pure state machine, every crash path a literal-event
test), `store/index.ts` (sole owner of status changes), `license/index.ts`
("no photo" is a normal result), `shortlist/index.ts` (pure, every drop
explained), `render/index.ts` (`renderHtml` pure, `renderSlides` the browser),
the three vendor adapters, and `doctor/index.ts` (returns results, prints
elsewhere).
